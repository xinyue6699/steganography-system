# 🖥️ 隐写系统前端页面

## 📋 项目概述

隐写系统前端页面是**基于 GAN 的生成式 MIDI 隐写系统**的 Web 前端展示页面，主要用于提供生成式音频隐写系统的用户交互界面。

系统采用 B/S（Browser/Server）架构，用户可以通过浏览器访问系统页面，并完成秘密信息隐藏以及秘密信息提取等操作。

前端主要提供以下功能：

- 隐写系统主页展示；
- 秘密信息输入；
- MIDI 隐写文件生成交互；
- MIDI 文件上传；
- 隐藏信息提取；
- 生成 MIDI 音频展示；
- 系统功能导航。

本仓库主要包含**隐写系统的前端页面以及静态资源文件**，GAN 音频隐写算法、模型训练以及 MIDI 信息提取等核心算法由后端服务完成。

## 🔐 2. 秘密信息隐藏

系统提供秘密信息输入功能。

用户可以在页面中输入需要进行隐写的秘密信息，并向后端发送生成请求。

整体业务流程为：

```text
用户输入秘密信息
        ↓
前端提交数据
        ↓
后端隐写算法
        ↓
秘密信息映射
        ↓
GAN Generator
        ↓
生成载密 MIDI
        ↓
返回前端
```

后端接收到用户提交的秘密信息后，通过生成式 MIDI 隐写算法生成包含秘密信息的 MIDI 音频。

生成完成后，前端负责向用户展示或提供生成结果。

---

## 🎵 3. MIDI 隐写文件生成

传统音频隐写通常需要：

```text
原始音频
   +
秘密信息
   ↓
修改音频数据
   ↓
载密音频
```

本系统采用生成式隐写方式：

```text
秘密信息
   ↓
噪声向量
   ↓
GAN Generator
   ↓
生成 MIDI
```

即直接根据秘密信息生成新的 MIDI 音乐文件。

前端主要负责：

- 获取用户输入；
- 提交生成请求；
- 接收生成结果；
- 展示生成的 MIDI 文件；
- 提供音频相关交互。

---

## 🔓 4. 秘密信息提取

用户获得包含秘密信息的 MIDI 文件后，可以通过系统上传该文件。

整体流程如下：

```text
用户上传 MIDI
       ↓
前端提交文件
       ↓
后端 Extractor
       ↓
恢复噪声向量
       ↓
秘密信息映射
       ↓
恢复秘密信息
       ↓
返回前端
```

系统后端通过训练好的秘密信息提取模型，对上传的载密 MIDI 进行分析，并恢复其中隐藏的秘密信息。

前端最终将恢复结果展示给用户。

## 🎯 项目特点

### 1. Web 可视化交互

将生成式音频隐写算法封装为用户可操作的 Web 页面，降低算法使用门槛。

前端主要负责：

- 页面展示；
- 数据提交；
- 文件上传；
- 结果展示。

后端负责：

- GAN 模型调用；
- MIDI 音乐生成；
- 秘密信息映射；
- 隐藏信息恢复。

使整个系统的功能划分更加清晰。
